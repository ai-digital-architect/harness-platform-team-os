# Graph node authoring rules

Apply when writing or editing files under `knowledge/`.

1. **Read GRAPH-SCHEMA.md first.** Frontmatter must include `id`, `type`,
   `title`, `status`. `id` must equal the path under `knowledge/` (without
   the `.md` suffix).
2. **status starts at `draft`.** Only humans promote to `active`. Never
   self-promote.
3. **Closed edge vocabulary.** Only use rels defined in GRAPH-SCHEMA.md
   (`depends-on`, `deploys-to`, `publishes-to`, `consumes-from`,
   `implements`, `touches`, `governed-by`, `affected-by`, `supersedes`,
   `subtree-of`). Extending the vocabulary requires a PR to the schema.
4. **Edge targets must resolve** — either to an existing node id or, for
   repo-shaped edges, to a name in `repo-manifest.yaml`.
5. **Never duplicate manifest facts.** If the fact lives in
   `repo-manifest.yaml`, edge to it; do not restate it in prose.
6. **No invented facts.** Use the `repo-surveyor` sub-agent for code-repo
   claims; mark gaps `TODO(verify): <question>`.
7. **Workflow nodes ship an ORDERED `repos:` list** plus per-step commands
   and a Verification section. Tribal-knowledge gaps → `[HUMAN]` marker.
8. **Never hand-edit** `knowledge/INDEX.md` or `knowledge/graph.json` —
   both are CI-generated by `scripts/build_index.py`.
9. **Run `python3 scripts/graph_check.py`** before finishing; the
   PostToolUse hook also runs it. Fix errors before continuing.
